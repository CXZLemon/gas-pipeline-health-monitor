# 项目原理与学习路线

## 1. 项目解决什么问题

天然气管道在运行中会持续产生入口压力、出口压力、流量和温度等时序数据。泄漏、堵塞、阀门异常或传感器漂移都可能使数据分布发生变化。真实现场的异常标签往往很少，因此本项目先使用无监督异常检测建立一个轻量级基线：模型学习大多数正常数据的分布，再把难以归入正常分布的记录标记为疑似异常。

项目不是安全诊断系统，而是一个“数据筛查器”。它的价值是从大量记录中找出值得工程人员优先检查的时间点。

## 2. 数据如何产生

合成数据用正弦周期模拟每天的用气波动，并叠加随机噪声：

- 流量包含日周期、周周期与随机波动。
- 入口压力围绕稳定值小幅变化。
- 出口压力由入口压力减去随流量变化的压降得到。
- 温度具有日周期。

随后随机注入三类异常：

- 泄漏：出口压力明显降低，同时流量升高。
- 堵塞：压降增大，同时流量降低。
- 传感器漂移：压力或温度出现不合理跳变。

注入标签仅用于验证模型有没有找到已知异常，不参与 Isolation Forest 的训练。

## 3. 特征工程做了什么

原始变量不能完整描述变化速度和局部趋势，因此增加：

- 压降：入口压力减出口压力。
- 压降比：压降除以入口压力，用于减弱不同压力等级的影响。
- 流量变化：相邻时刻流量差的绝对值。
- 压降滚动均值：描述最近一段时间的局部基线。
- 压降滚动标准差：描述局部波动程度。
- 小时正余弦编码：用两个连续变量表达 23 点与 0 点在时间上相邻。

## 4. Isolation Forest 如何工作

Isolation Forest 反复随机选择一个特征和切分值，把样本分开。普通样本通常位于密集区域，需要多次切分才能单独隔离；异常样本数量少且取值特殊，通常经过较少切分就会被隔离。多棵随机树的平均路径长度可以转换成异常分数。

本项目先用 StandardScaler 标准化特征，再训练 250 棵隔离树。`contamination` 表示预计异常比例，它会影响最终阈值，但不会改变原始风险排序。

## 5. 数据库模块

SQLAlchemy 用统一接口支持不同数据库：

- 默认 SQLite，单文件、无服务、适合本地演示。
- 把 `DATABASE_URL` 改成 MySQL 连接串即可切换到 MySQL。
- 查询使用参数绑定，不把用户输入直接拼入 SQL。

学习时可以先掌握表写入、条件查询和事务，再增加主键、联合索引与批量写入性能对比。

## 6. 推荐的 5 天学习顺序

### 第 1 天：数据与业务

运行 `generate_synthetic_data`，画出四个原始变量，解释正常波动和三类异常的差别。

### 第 2 天：Pandas 特征工程

逐行理解 `features.py`，重点练习 `groupby`、`diff`、`rolling`、缺失值处理和时间字段。

### 第 3 天：异常检测

学习标准化、训练、`predict` 与 `decision_function`。修改 `contamination`，观察 Precision 和 Recall 的变化。

### 第 4 天：可视化和数据库

运行 Streamlit 页面，理解筛选、图表、缓存与下载按钮；再运行命令行脚本检查 SQLite 数据。

### 第 5 天：测试与项目表达

逐个运行测试，故意修改一个函数使测试失败，再恢复。最后按照面试指南完成 1 分钟介绍和五个常见问题。

## 7. 必须理解的局限

1. 合成数据比真实数据简单，指标不能作为现场效果。
2. 随机划分不适合时序评估，真实项目应按时间切分训练期和测试期。
3. 无监督模型只能识别统计异常，不能自动证明异常原因。
4. `contamination` 需要依据历史数据、告警成本和人工处理能力确定。
5. 上线时需要数据漂移监控、告警去重、人工确认和模型版本管理。
